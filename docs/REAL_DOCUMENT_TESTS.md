# 실제 문서 시험

자비스의 문서 처리 정확도와 실행 환경별 한계를 확인하는 관리자용 수동 시험 기준이다. 시험 계획이나 지침 검사 통과를 실제 문서 시험 통과로 보고하지 않는다. 모든 사용자 요청에 이 시험 절차를 강제하지 않는다.

## 자료와 기준 준비

- 공개 자료 또는 시험 사용이 허용된 자료를 선택한다. 공고와 신청서는 같은 사업·차수·버전인지 확인한다. 회사의 비공개 원본·개인정보·추출 본문은 GitHub에 올리지 않는다. 공개 기록에는 개인 경로 대신 사례 ID와 공개 출처를 쓴다.
- 실행 전에 원본을 직접 확인해 확인 대상과 정답을 정한다. 각 정답에 원본 쪽·항목·표·셀 위치와 단위·조건을 연결한다. 같은 추출 도구의 출력만을 정답으로 삼지 않는다.
- 입력 자료의 버전 또는 해시, 요청문, 지침 버전 또는 커밋, 사용 앱·모델·도구·설정·접근 권한을 기록한다. 제공되지 않는 모델 세부 정보는 미확인으로 남긴다. 원본과 결과물은 분리해 보존한다.

## 시험 사례

| 사례 | 실행 전 정할 확인 대상 | 통과 기준 |
| --- | --- | --- |
| 공고와 신청서 | 신청 자격·마감일·지원 한도와 조건·필수 작성란·첨부서류 목록 | 원본 기준의 모든 대상 항목을 대조하고 사실·단위·조건을 유지한다. 자격 증빙이 없으면 충족으로 단정하지 않는다. 작성란에 근거가 없으면 확인 필요로 남긴다. |
| 병합 셀·반복 항목이 있는 HWP·HWPX | 입력할 칸의 위치와 값, 변경하지 않을 칸 | 같은 항목명을 위치·문맥으로 구분한다. 편집 시험은 저장된 파일에서 대상 칸의 값과 주변 항목을 다시 확인한다. 읽기만 성공한 결과를 편집 성공으로 보지 않는다. |
| 스캔·텍스트 혼합 PDF | 쪽별 본문·표·중요 숫자와 이미지 페이지 | 이미지 페이지를 누락하지 않고 추출된 글자를 원본 화면과 대조한다. OCR을 수행했는지와 남은 오독·미검증 쪽을 구분한다. |
| 길이가 긴 문서 | 앞·중간·끝에 실제로 있는 항목과 필요한 전체 범위 | 잘림·부분 추출이 발생하면 남은 내용을 추가 확인한다. 끝부분 일부를 찾은 것만으로 전체를 읽었다고 판단하지 않는다. 접근하지 못한 범위는 미검증으로 보고한다. |
| 기존 계획서 문체 수정 | 수정 전 수치·단위·기간·조건·인용·예정/완료 상태 | 지정된 문체를 수정하되 고정된 사실과 의미를 유지한다. 발견한 모순은 임의로 고치지 않고 별도로 보고한다. |

## 판정과 기록

확인 대상마다 기대 결과, 실제 결과, 원본 위치, 결과물 위치와 판정을 남긴다. 판정은 통과·실패·미검증·해당 없음으로 구분하고, 해당 없음의 이유도 적는다. 도구나 권한 부족으로 수행하지 못한 기능은 미검증이다. 이를 정확히 보고했다면 한계 보고 기준은 통과할 수 있지만, 해당 기능이 검증된 것은 아니다. 필수 확인 대상에 실패나 미검증이 있으면 그 시험을 전체 통과로 표시하지 않는다.

| 기록 항목 | 작성 내용 |
| --- | --- |
| 사례·입력 | 사례 ID, 자료 버전 또는 해시, 공개 출처 또는 권한 있는 내부 보관 위치 |
| 환경·요청 | 앱·모델·도구·설정·권한, 지침 커밋, 실제 요청문 |
| 기대 결과 | 확인 대상별 정답·허용된 변경·원본 위치 |
| 실제 결과 | 결과물과 대조 위치, 확인한 내용과 수행하지 못한 범위 |
| 판정 | 대상별 통과·실패·미검증·해당 없음과 이유 |
| 보완·재시험 | 원인, 변경 사항, 같은 사례 재시험 결과와 남은 한계 |

## 실패에 따른 보완

| 관찰한 현상 | 먼저 확인할 원인 | 보완 방향 |
| --- | --- | --- |
| 읽은 항목을 작성에서 빠뜨림 | 실제 읽기 범위와 항목 대응 기록 | 항목 점검·집필 지침 보완 |
| 표·이미지·글자를 추출하지 못함 | 원본 구조, 도구 지원과 추출 경고 | 처리 도구·변환 경로 검토. 지침 추가만으로 해결했다고 판단하지 않음 |
| 수정하면서 숫자·조건·상태가 달라짐 | 변경 전후 대조와 저장 결과 | 변경 범위·사실 보존·재읽기 절차 보완 |
| 미확인 작업을 완료했다고 보고함 | 실제 수행 기록과 완료 표현 | 완료 판단과 한계 보고 기준 보완 |

원인을 확정하지 못하면 원인 미확인으로 기록한다. 수정 후 같은 입력과 확인 기준으로 다시 시험하고, 영향을 받는 관련 사례를 확인한다. 이전 기대 결과를 바꿔 실패를 숨기지 않는다. 기준을 정정해야 한다면 원본 근거와 변경 이유를 기록한다.

문서 처리 정확도와 다른 환경에서의 실행 가능성은 별도로 판정한다. 배포 대상 환경마다 설치·파일 접근·필요 도구·실제 읽기 또는 편집을 확인하며, 한 PC의 통과를 웹·다른 OS·다른 계정의 통과로 확대하지 않는다. 같은 실행 조건을 제공할 수 없으면 차이를 기록한다.

## 현재 실행 상태

이 문서는 시험 기준이다. 추가 시점에 위 실제 문서 시험을 수행한 결과는 기록하지 않았다. 실제 결과가 생기면 별도 시험 기록에 남기며, 기존의 대화형 업무 시험과 구분한다.
