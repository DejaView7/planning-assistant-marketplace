# 필요한 작업에만 적용하는 관점 간 협업

## 적용 여부
같은 사실을 서로 다른 기준으로 검토해야 결과가 달라지는 작업에 적용한다. 전체 사업 방향·아이템 선택·요금제·수익모델·중요한 개발 범위·인력/예산/일정의 타당성·전체 초안의 핵심 논리 검토가 해당한다. 단순히 문서가 길거나 '검토'라는 단어가 있다는 이유로 적용하지 않는다.
요약·번역·문체 변경·글자 수 축약·오탈자·정해진 표 수정에는 해당 담당 관점만 사용한다. 확정값 변경은 우선 변경 관리로 관련 산식·문장을 갱신하고, 그 변경이 구매 가능성·실행 가능성 등 새로운 판단을 요구할 때만 추가 관점을 적용한다. 복잡성이나 확인할 근거가 부족하면 불필요한 역할을 늘리기보다 핵심 가정·필요 자료를 식별한다.

## 선택 예시
| 요청 | 필요한 관점과 확인할 결정 |
|---|---|
| 500자 이내로 줄이기 | 문서 편집만 적용, 의미·수치·상태 보존 후 실측 |
| 사업 필요성의 설득력 검토 | 고객·시장 → 심사 관점, 문제의 근거와 지원 필요성 연결 |
| 기관용 요금제 설계 | BM·재무 → 영업/구매자, 원가·지원 범위와 구매조건 확인 |
| 공고에 맞는 사업 방향 추천 | 고객·시장 → 제품·운영 → 재무, 수요·구현·기간·비용 연결 |
| 확정 가격만 변경 | 관련 매출·예산·제안 문구 갱신, 요청 없이 요금제 전체 재설계 금지 |
| 전체 초안의 핵심 약점 개선 | 약점이 있는 2~3개 관점만 선정해 검토·본문 수정 |

고객·시장, 제품·데이터·운영, BM·재무, UX·영업·구매자, 심사 관점을 현재 업무에 맞게 선택한다. 기본은 관련 관점 2~3개이며 모든 역할의 보고서를 매번 생성하지 않는다. 더 많은 관점은 사용자가 요청하거나 새로운 독립 쟁점이 실제로 드러난 경우에만 추가한다. 해당 전문 모듈과 근거·집필 지침은 통합 메인 선택표에서 선택한다.

## 역할 간 전달과 상호 검토
1. **공통 기준 고정:** 대상 회사·고객/구매자·제품 현재/예정 범위·기간·가격/단위·예산·사용자 결정·요청 산출물과 핵심 미확인을 필요한 만큼 정리한다. 이후 역할이 임의로 값을 바꾸지 않는다.
2. **앞 관점의 결과 작성:** 결론·직접 근거·가정/미확인·다음 관점이 판단할 입력을 남긴다. 공개 확인 사실과 회사 제공 사실을 구분하고, 자료 없는 주장을 확정값으로 전달하지 않는다.
3. **다음 관점의 검토:** 전달받은 결과가 자기 기준에서도 성립하는지 확인한다. 예를 들어 기술 기능의 운영 부담·원가를 검토하거나, 가격안의 구매자 수용 조건을 확인한다. 앞 역할의 결론을 반복하거나 동의하는 것만으로 검토를 대신하지 않는다.
4. **충돌 수정:** 고객 문제·기능·가격·인력·일정 등이 충돌하면 해당 근거와 영향을 확인하고 관련 부분만 앞 단계로 돌려 수정한다. 필요하면 다른 대안·범위 축소·조건부 추천을 제시한다. 회사 사실이나 전략 선택이 반드시 필요할 때만 질문하고 독립 작업은 계속한다.
5. **통합:** 중복·충돌·단위·가정 상태를 정리해 하나의 추천안과 실제 본문·표를 작성한다. 변경된 결정이 연결된 요약·예산·일정·파일에도 반영되었는지 확인한다. 더 나은 근거가 없으면 합의한 것처럼 꾸미지 않고 남은 불확실성을 표시한다.

## 범위와 종료
관점 검토와 통합을 기본 한 차례 수행하고, 결과를 바꾸는 충돌이 있을 때 해당 부분을 추가 검토한다. 중요한 미해결 쟁점이 없거나 가능한 수정과 남은 확인사항이 정리되면 결과를 전달한다. 표현 개선을 이유로 역할을 반복 순환하거나 모든 의견의 일치를 기다리지 않는다. 부분 수정은 새 요청과 필수 영향만 다루며 이전 분석 전체를 재실행하지 않는다.

## 사용자에게 보여줄 결과
실제 초안·추천안·수정 결과를 중심으로 전달한다. 협업 때문에 달라진 중요한 판단이 있을 때만 선택 이유·해결한 충돌·남은 확인사항을 짧게 설명한다. 역할별 긴 대화·내부 사고과정·형식적인 토론 기록을 출력하지 않는다.
이 절차는 현재 에이전트가 여러 전문 관점을 적용하는 방식이다. 실제 여러 전문가 또는 독립된 AI가 검증했다고 표현하지 않는다. 추가 에이전트 실행·다른 모델 호출·별도 플러그인 호출을 자동으로 요구하지 않는다. 사실 검증은 역할 수가 아니라 접근한 원자료와 확인 범위로 설명한다.
