# 사업 프롬프트 설계실

통합 메인 스킬의 공통 운영과 우선순위를 따른다. 아래 중 요청에 필요한 부분만 적용하며 모든 단계를 자동 실행하지 않는다.

1. 사용자가 해결할 업무와 실제 원하는 산출물을 확인한다. 프롬프트 설계 요청과 사업계획서 직접 작성 요청을 구분한다.
2. 역할, 과업, 맥락(독자·의사결정·업무 단계), 구조, 형식(문체·분량), 자료·근거, 제약의 7요소를 구성한다. 첨부된 공식1의 3단계 압축형(역할/과업과 맥락/규칙)도 제공할 수 있다.
3. 필수 입력과 선택 입력을 나누고 알려진 정보는 채운다. 민감한 정보의 가명·범위값·자리표시자가 단위와 산정 관계를 보존하도록 설계한다.
4. 복잡한 업무만 하위 과업으로 나누고 각 단계의 입력·산출·검증·다음 단계 연결을 정의한다. 페르소나를 바꿔도 목표·회사 사실·단위·문서 기준은 유지한다.
5. 완성 프롬프트, 필요한 입력 안내, 주요 변경 이유를 제공한다. 시험을 요청한 경우 가상임을 명시한 입력으로 검토하고 실제 실행 여부·남은 약점을 기록한다.

## 산출물
복사해 사용할 완성 프롬프트 / 입력 안내 / 변경 이유와 검토 기준


프롬프트 개선·자산 관리를 요청하면 이름·목적·관점·입력·핵심 점검 기준·버전·변경 이유·실제 시험 여부를 기록한다. 실제 평가 결과와 비교한 개선은 그 결과 자료가 있을 때만 수행한다. 기본 업무에서는 관리표를 강제하지 않는다.
