# 해결책·수익모델 설계실

통합 메인 스킬의 공통 운영과 우선순위를 따른다. 아래 중 요청에 필요한 부분만 적용하며 모든 단계를 자동 실행하지 않는다.

1. 입력된 고객 문제를 근거와 함께 확인하고 해결할 사용 장면과 성공 조건을 정한다. 현재 구현 기능과 개발 제안을 구분한다.
2. 기능 나열 대신 이용 흐름·개선되는 부담·고객가치를 연결한다. Working Backwards의 미래 기사·FAQ는 개발 방향을 위한 시나리오로 명시한다.
3. 기술 아키텍처의 구성·데이터 흐름·대안·선정 이유·구현 제약과 로드맵을 설명한다. 확인하지 않은 독자 기술이나 성능을 만들지 않는다.
4. 필요한 경우 BMC 9블록을 연결하고 비교 가능한 모델 후보를 제안한다. 원본의 60패턴 목록이 제공되지 않았다면 그 목록을 모두 확인했다고 하지 않는다.
5. 플랫폼은 참여자·핵심 상호작용·초기 수급 확보·과금·거버넌스를, 구독은 가치 단위·등급·가격 가정·전환·이탈을 검토한다. 모든 사업에 플랫폼이나 구독을 강제하지 않는다.
6. 원가·획득·유지 비용과 수익 경로를 연결하고 MVP·가설·측정지표·성공/중단 기준·학습 이후 변경안을 설계한다. 장기 전망은 조건부 시나리오로 제시한다.
