# 결과물 예시와 오류 사례

모두 형식을 설명하기 위한 가상 사례다. 실제 기업·공고·가격·실적의 근거가 아니다. 요청의 분량과 양식에 맞춰 조절한다.

## 사업 방향 검토
입력: 지역 복지시설이 이용자의 프로그램 참여를 높일 방안을 찾음. 예산과 실제 참여 기록 미제공.
좋은 결과: 기존 프로그램 안내·참여 신청 지원을 우선 후보로 제안하고, 신규 장비 도입안과 운영 부담·이용자 접근성·검증 비용으로 비교한다. 대상자 인터뷰와 기존 참여 기록을 확인한 뒤 범위를 정한다. 참여 증가율이나 구매 의사를 실적으로 쓰지 않는다.
오류: “AI 플랫폼을 도입하면 참여율이 30% 상승한다”처럼 확인되지 않은 효과를 단정하거나 대안 비교 없이 기술을 먼저 선택한다.

## 공고·신청서 작성
입력: 양식 항목은 기업정보·제품 개요·활용계획. 기업명만 확인되고 연락처·예산 미제공.
좋은 결과: 기업정보의 확인된 기업명은 실제 작성란에 넣고 연락처는 확인 필요로 남긴다. 제품 개요와 활용계획은 제공한 자료로 본문을 작성한다. 원본을 편집했다면 입력 위치와 값을 재확인하고, 별도 문서라면 원본에 옮길 검토본이라고 보고한다.
오류: 대항목 아래에 초안 전체를 붙인 뒤 각 칸을 채웠다고 보고하거나, 지역 협력 이력만으로 소재지 자격을 충족한다고 판단한다.

## 고객 제안서 작성
입력: 고객은 정기 운영 보고를 원하며 월 단가·인력과 계약 기간은 미확정.
좋은 결과: 제공 자료를 기반으로 보고서의 항목·작성과 검토 역할·고객 확인 절차를 제안하고, 제공 횟수·기간·가격은 제안인지 확인 필요인지 밝힌다. 가격 근거를 확보할 자료와 범위 변경 시 영향은 내부 메모에 연결한다.
오류: 기존 단가가 없는데 확정 견적을 창작하거나 미정 인력의 투입과 납기를 약속한다. 예시의 해외 결제 조건을 기본 계약 조건으로 복사하지 않는다.

## 기존 문서 보완
입력: 문체만 정리하고 금액과 수치는 바꾸지 말라는 요청.
좋은 결과: 문장을 실제 수정하되 기존 수치·주장 상태를 유지한다. 숫자에 모순이 있으면 임의로 고치지 않고 별도 보고한다. 주요 수정은 문체·중복 정리로 설명한다.
오류: 문장을 자연스럽게 고치면서 “실증 예정”을 “효과 입증”으로 바꾸거나, 사용자가 고정한 금액을 계산 결과에 맞춰 변경한다.

## 보고의 공통 예
“지정 항목에 맞춘 검토용 초안을 작성했습니다. 연락처와 견적은 확인이 필요합니다. 파일 본문은 재확인했으나 페이지 렌더링은 수행하지 못해 배치는 미검증입니다.”
실제 결과에 없는 검사·파일·근거를 보고 문구에 추가하지 않는다. 최종 메시지는 파일 링크와 핵심 부족 사항을 포함하며 원본 편집 여부와 검증 범위를 정확하게 설명한다.
