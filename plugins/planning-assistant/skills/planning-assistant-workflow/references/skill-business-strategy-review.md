# 사업 전략 검토·개선실

통합 메인 스킬의 공통 운영과 우선순위를 따른다. 아래 중 요청에 필요한 부분만 적용하며 모든 단계를 자동 실행하지 않는다.

1. 검토 목적·초안·공고·판단 기준을 파악하고 결과를 바꾸는 쟁점만 고른다. 단순 문장 수정에 전체 심화 절차를 강요하지 않는다.
2. 대안 탐색은 구별되는 후보를 만든 뒤 기준·장단점·근거·불확실성으로 비교한다. 점수가 유용할 때만 기준·가중치·민감도를 설명한다.
3. 스텝백은 핵심 원칙과 제약을 정리한 후 실제 전략·행동·예산·KPI로 내려온다. 추상적 원칙만 제시하고 끝내지 않는다.
4. 지식 생성은 필요한 조사 질문·용어·가설을 정리하는 준비 단계다. 생성된 지식을 검증된 자료로 취급하지 않고 원출처를 확인한 뒤 최종 분석에 사용한다.
5. 문제 분해는 독립적인 기초 문제부터 해결하고 앞 단계의 주장·단위·고객·목표·근거를 검증한 후 다음 단계로 넘긴다. 오류나 변경이 있으면 영향받는 후속 결과도 수정한다.
6. 다양한 니즈 탐색은 근거·잠재력·장벽·검증 우선순위로 비교한다. 원본이 성장확률 %를 요구해도 자료·모형 없이 실제 확률을 꾸미지 않는다.
7. 심사 관점은 수익·기술·팀·영업·확장으로 검토하되 실제 여러 전문가의 독립 심사나 합격 보장이 아니다. 공고가 있으면 실제 평가기준을 우선한다.
8. 가장 중요한 약점·근거·영향·추천 수정안·확인할 결정을 제시하고 가능한 수정은 실제 본문에 반영한다. 생성→검토→개선의 변경과 남은 한계를 제공한다.

관점 간 전달과 통합이 필요한 경우 선택적 협업 (지침: [method-collaboration](method-collaboration.md))을 적용한다. 단순 수정에 다중 관점을 강제하지 않으며 동일 AI의 관점 검토를 독립 검증으로 취급하지 않는다.
